# Where a Workshop item's data lives

Every Workshop item is owned by one folder in its project (for a mod, the mod's own folder). That folder holds the item's
identity and its publishing metadata in `workshop/`. The shared scripts in `scripts/` read this layout and never store
project data themselves.

```
<item-dir>/
  workshop/
    workshop.json        identity, visibility, languages, content and preview paths (committed)
    description.<code>.txt  one Steam BBCode description per uploaded language, english and schinese (committed)
    preview.png          the Workshop preview image (committed, under 1 MB recommended)
    .gitignore           ignores .build/
    .build/              generated by pack/upload: staged content and translations.json (not committed)
```

Create it with `workshop.py init <item-dir> --app-id <AppID> --languages english,schinese`, then fill in the TODO parts.

## workshop.json

```json
{
  "schema": 1,
  "appId": 4348910,
  "publishedFileId": "0",
  "visibility": "public",
  "primaryLanguage": "english",
  "languages": {
    "english": { "title": "Item title", "description": "description.en.txt" },
    "schinese": { "title": "物品标题", "description": "description.zh.txt" }
  },
  "titles": { "en": "Item name", "zh-CN": "物品名称" },
  "contentPath": "../build/output",
  "include": ["manifest.xml", "*.dll"],
  "previewPath": "preview.png",
  "tags": ["Mod", "Gameplay"],
  "screenshots": ["screens/01-menu.png", "screens/02-ingame.png"],
  "videos": [{ "youtubeId": "dQw4w9WgXcQ", "title": "Demo (English)" }],
  "changeNote": "中文：修复存档读取问题，优化加载速度。\nEnglish: Fixed a save-loading bug and improved load speed."
}
```

| Field | Rule |
| --- | --- |
| `schema` | `1`. |
| `appId` | Required. The Steam AppID of the game. No default is assumed. |
| `publishedFileId` | `"0"` until the first upload. `upload` writes the id Steam returns, once. After that it is only read; never edit, clear or copy it by hand. |
| `visibility` | `public` (the default for every item), `friends`, `hidden` (Steam "Private") or `unlisted`. Use `hidden` only for a private test the user asks for, and set it back to `public` afterwards. |
| `primaryLanguage` | `english` or `schinese` (`en` and `zh-CN` also accepted). Its text is sent with the content; the other allowed language is sent afterwards as a text-only update. |
| `languages` | Steam language code to `{title, description}`. Only `english` and `schinese` are uploaded (`en`, `zh`, `zh-cn`, `zh-hans` count as those two); any other key is skipped with a `skip:` line and never sent. `title` is at most 128 characters, or the composed title when `titles` is set; `description` names a file inside `workshop/`, Steam BBCode, at most 8000 UTF-8 bytes (not characters; Steam refuses longer text). |
| `titles` | Optional `{"en": "<English segment>", "zh-CN": "<Chinese segment>"}`. When set, each uploaded language's title is composed from the segments: `schinese` gives Chinese, ` \| `, English; `english` gives English, ` \| `, Chinese. A missing segment is left out with no separator. The composed title is at most 128 characters and is checked before anything is staged. Keys are normalized like `languages` keys; an unknown key is an error. Composition happens in memory and this file is never rewritten. Without `titles`, the stored `title` is uploaded unchanged. |
| `contentPath` | Required. The folder to upload, relative to `workshop/` (or absolute). The project builds or prepares it; the scripts only copy from it. |
| `include` | Optional list of glob patterns relative to `contentPath` (`*` also matches across `/`). Without it, every file is uploaded. Use it to upload only what the game accepts. |
| `previewPath` | Relative to `workshop/`. Default `preview.png`. The main Workshop preview. |
| `tags` | **Required** (`[]` for none). The Steam Workshop tags of this game, each name exactly as Steam writes it. Tags are per game: this skill never picks, guesses or copies them. `check` verifies each one against the list Steam declares for `appId` (the game's Workshop page, `readytouse_tags`, cached 24 hours); `workshop.py tags <item-dir>` prints that list. Sent with every `upload --yes`: an empty list clears the tags on Steam. |
| `screenshots` | Optional list of extra screenshots (Steam additional previews), relative to `workshop/`. Types `.png .jpg .jpeg .gif` (this skill's rule). File names must be unique: Steam lists them by name. Sent with `images upload --yes`; removed with `images remove <file-name> --yes`, which also drops the entry here. |
| `videos` | Optional list of `{"youtubeId", "title"}`: the YouTube videos shown on the item page. A record only: Steam takes Workshop videos as YouTube links added by hand on the item page, and no script sends them. `youtubeId` is the 11-character id (not a URL); ids are unique; `title` is required. `workshop.py videos list <item-dir> [--remote]` shows them. |
| `changeNote` | **Required.** The change note sent with every `upload --yes`: exactly two lines, `中文：<中文说明>` then `English: <English description>`, at most 300 characters in all, no `TODO`. `--changenote` replaces it for one upload and must pass the same rule. Checked by `check`, `pack` and `upload`. |

## Visibility names

| Name | Steam value | Meaning |
| --- | --- | --- |
| `public` | 0 | Visible to everyone. |
| `friends` | 1 | Friends only. |
| `hidden` | 2 | Private: only the owner sees it. |
| `unlisted` | 3 | Reachable by link, not listed. |

Values come from the steamworks.js typings (`UgcItemVisibility`).

## Who owns what

| Data | Owner |
| --- | --- |
| The layout, the scripts, the upload rules and traps | This skill (`steamworks-workshop-publish`). |
| `publishedFileId`, titles, descriptions, preview, `contentPath`, `include` | The item's own folder, committed to its project. |
| How the content is built (compile, copy DLLs, game-specific validation) | The project. Put it in the project's build step, then point `contentPath` at the result. |
| Project-specific brand text | The project, or the shared description skill that owns it. |

## Migrating an existing item

1. Keep the existing `publishedFileId` exactly as it is; copy it into the new `workshop.json`.
2. Convert numeric `visibility` to a name (`0` public, `1` friends, `2` hidden).
3. Add `appId` and `contentPath` (and `include` if the old build folder held extra files).
4. Run `check`, then `pack`, then `upload` without `--yes` to see the plan before anything is sent.

## Rules the scripts enforce

- Nothing is sent unless `upload` gets `--yes`.
- `check` stops when `tags` is missing, is not a list of exact names, repeats a name, or names a tag Steam does not declare for `appId`. When the declared list cannot be read (no page, no cache, no `WORKSHOP_TAGS_FILE`), it stops too, rather than skipping the comparison.
- `changeNote` must be the bilingual two-line note (see the publish skill's Change note section); `check`, `pack` and `upload` refuse anything else, including an empty note.
- `publishedFileId` changes only from `"0"` to the id Steam returns for a new item.
- A failed upload after creation keeps the id; run the same command again, which updates that item.
- A `.git` folder in the upload is refused.
- Titles, descriptions and the preview are checked for `TODO` placeholders before anything is sent.
- Only `english` and `schinese` are uploaded. Other languages get a `skip:` line, and the exit code stays 0.
- A `primaryLanguage` outside `english`/`schinese`, an item with no allowed language, and a composed title over 128 characters stop the run before anything is staged.
- `upload` is the one route to Steam. `steam-workshop.mjs` refuses any language other than `english` and `schinese`.

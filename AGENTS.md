# steamworks.js

Notes for AI coding assistants. Everything below was checked against the repository files.

## Overview

- `@ducky7go/steamworks.js` (`package.json`, version `0.0.1` as committed; real versions are set by CI): Node/Electron bindings for the Steamworks SDK. Rust native layer (`napi` 2.16 + `napi-derive`, crate `steamworksjs`, `cdylib`) wrapping `steamworks-rs`, plus a thin JS loader (`index.js`) and hand-maintained type declarations.
- The README describes it as a replacement for greenworks. It is the ducky7go fork of the community `steamworks.js` project (fork-specific work: Workshop update/preview/multilingual APIs, disconnect handling, scoped npm package). No `upstream` remote is configured in this checkout, so the exact upstream repo was not verified.
- Related repo in the same org: `steamworks-rs` (the vendored submodule).

## Layout

- `src/lib.rs`, `src/client.rs`, `src/api/*.rs` - one Rust module per Steam feature (`achievement`, `apps`, `auth`, `callback`, `cloud`, `input`, `localplayer`, `matchmaking`, `networking`, `overlay`, `stats`, `utils`, `workshop`, `workshop_item`).
- `vendor/steamworks-rs` - git submodule (`.gitmodules`: `https://github.com/ducky7go/steamworks-rs.git`), a path dependency in `Cargo.toml` with features `serde` and `raw-bindings`. In a shallow/non-recursive clone this directory is empty; run `git submodule update --init --recursive` before building. Sibling repo `steamworks-rs` is the source of that submodule.
- `build.js` - copies the Steam redistributable library from `vendor/steamworks-rs/steamworks-sys/lib/steam/redistributable_bin/<folder>` into `dist/<folder>` and runs `napi build` for the chosen target.
- `index.js` loads `dist/<win64|linux64|osx>/steamworksjs.<triple>.node`; supported: win32-x64, linux-x64, darwin-x64, darwin-arm64.
- `client.d.ts` is generated by the build (`build.js` passes `--dts ../../client.d.ts`) but is tracked in git; `index.d.ts` and `callbacks.d.ts` are hand-written.
- `test/` - plain Node scripts (`auth.js`, `workshop.js`, ...), `test/electron/` app, `test/typescript/` type-check project. `openspec/` holds specs (`ci-cd`, `client-lifecycle`, `npm-publish`, `steamworks-dependency`, `version-management`, `workshop-queries`) and an archive of past changes.

## Build, test, format

- Build (needs Node, Rust, Clang, and a recent `vendor/steamworks-rs` checkout): `pnpm install`, then `pnpm run build:debug` (or `pnpm run build` for `--release`). Cross-target builds are done only in CI; locally you build for your own platform. `pnpm run prune` removes `dist`, `target`, `client.d.ts`.
- Format/lint: `pnpm run format` (= `cargo clippy --fix --allow-staged && cargo fmt`). CI runs `cargo fmt --all --check` and `cargo clippy`.
- Type check (what CI runs in `typescript-smoke-test.yml`): `pnpm install`, then `cd test/typescript && pnpm install && pnpm run compile` (`tsc --noEmit --strict index.ts`).
- Other tests are manual and require a running Steam client (default AppID 480 in examples); see `test/README.md`. Electron check: `cd test/electron && pnpm install && pnpm start`.
- JS/TS style (`.prettierrc`): single quotes, no semicolons, trailing commas, 4-space tabs, print width 140, LF.

## Conventions

- Conventional Commits (`feat`, `fix`, `docs`, `refactor`, `test`, `build`, `ci`, ...); breaking changes marked with `BREAKING CHANGE:` in the body (`CONTRIBUTING.md`).
- Release flow (`.github/workflows/publish.yml`, `GitVersion.yml`): pushing a `v*` tag publishes `<tag without v>` to npm `latest`; pushes to `main` publish the GitVersion `fullSemVer` to the `dev` tag. The deploy job only runs for `github.repository == 'ducky7go/steamworks.js'`. Linux and Windows binaries are built in an `ubuntu:20.04` container (Windows via `cargo-xwin`), macOS on `macos-latest`.
- Behavior/API changes are spec-driven: use OpenSpec (`openspec/AGENTS.md`); update `client.d.ts`/`index.d.ts` together with the Rust API.
- Workshop language codes are Steam API names (`english`, `schinese`, `french`, ...) passed as `language` to `updateItem` (see README "Workshop Multilingual Support").

## Gotchas

- `CLAUDE.md` is only a copy of the OpenSpec block plus release notes; its "dev version" rule (`{latest}-dev.{commit_count}`, queried from the GitHub API) does not match `publish.yml`, which uses GitVersion `fullSemVer`.
- `openspec/project.md` pins the submodule commit `9841b63...`; the current gitlink in HEAD is `59796fd88a3b88b93c66098d80a8077f70da0193`.
- `test/README.md` says `node tests/additional-previews-smoke-test.js` but the directory is `test/`.
- README still mentions copying from `sdk/redistributable_bin/...` for production Electron builds; `build.js` actually sources from `vendor/steamworks-rs/steamworks-sys/lib/steam/redistributable_bin`.
- Steam must be running and an AppID (`steam_appid.txt` or `init(appId)`) must be available for runtime tests. The Steamworks SDK is Valve's proprietary SDK (`openspec/project.md`).
- Changing the submodule pointer means a matching commit must exist in `ducky7go/steamworks-rs`.
